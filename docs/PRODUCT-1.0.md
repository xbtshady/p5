> 看到好照片 → 30 秒内记下来 → 以后能快速找到 → 慢慢形成自己的摄影参考库。

版本：1.0
最后更新：2026-09-15
仓库：https://github.com/xbtshady/p5

---

## 一、产品定位

### 核心循环

**收藏一张照片 → 写下自己的观察 → 以后重新看到它。**

这个循环做到非常顺，是 1.0 唯一的目标。

### 真正的产品价值

不是"帮你收藏照片"。是几年以后，你打开 `#低机位` 看到 37 张，再打开 `#人物与环境` 看到 52 张，然后发现：

> "原来我一直喜欢这种构图。"

再过一段时间，你拍摄时会开始主动寻找这些东西。这才是这个摄影手册真正的价值。

---

## 二、1.0 核心原则

1. **视觉优先**：手机上大图、少文字。
2. **所有文字可选**：刷到一张照片时可能只想记一句"这个角度以前完全没想过"，那也应该允许直接保存。不要用表单逼用户填完。
3. **首页是视觉博客，不是后台管理界面**：按时间倒序的照片流，不是 Dashboard。
4. **私人项目，无登录无多用户**：1.0 根本没有 User 表。

## 三、1.0 功能范围

### 3.1 首页：摄影手册

顶部：

```
我的摄影手册                         ＋
记录那些让我停下来多看一眼的照片
```

下方按时间倒序显示案例。每条案例 = 一张照片 + 简短信息：

```
┌─────────────────────┐
│                     │
│       照片          │
│                     │
└─────────────────────┘

低机位让我重新认识环境人像

2026.09.15

#低机位  #环境人像  #构图
```

**不要**一开始就做复杂的卡片、统计图、Dashboard。

### 3.2 新增摄影案例（最重要的一页）

点首页右上角 `＋` 进入：

```
新增摄影案例

[ 上传照片 ]

标题                  (可选)
________________

我为什么保存它？       (可选，直觉)
________________
________________

我注意到了什么？       (可选，提炼)
________________
________________

下次尝试               (可选，行动)
________________
________________

标签
[低机位] [构图] [+ 添加]

来源（可选）
________________

[ 保存 ]
```

**关键设计**：所有文字字段都可选。允许只写一句"这个角度以前完全没想过"就保存。

### 3.3 案例详情

点击一张照片：

```
┌─────────────────────┐
│                     │
│       大照片        │
│                     │
└─────────────────────┘

这个低机位很有意思

2026.09.15

我的观察

人物的位置并不特别，但摄影机的位置很低，
导致建筑和天空占据了大量画面。

下次尝试

拍环境人像的时候，主动尝试一次低机位。

#低机位  #环境人像  #构图

来源
Pinterest
```

**预留位**：详情页留一个"AI 分析"按钮的位置，但 1.0 不实现。

### 3.4 标签

预置标签（1.0 混用，1.5 拆维度）：

- **技法维度**：构图、角度、光线、色彩、姿势、镜头
- **题材维度**：环境人像、室内、夜景、街拍、场景

用户也可自建。

首页有"探索"区显示常用标签：

```
探索

#构图  #低机位  #逆光  #环境人像  #街拍
```

点击标签显示相关照片。这是未来非常重要的学习路径——"我最近想练低机位"，点 `#低机位` 看到所有收藏过的低机位照片，比按时间翻照片有价值得多。

### 3.5 搜索

1.0 做简单的文本搜索，匹配：标题、note、observation、nextAttempt、tags。

**不做** AI 语义搜索。等数据真的多了再考虑"找出所有和人物与环境关系有关的照片"这种语义检索。

## 四、字段语义定义

| 字段 | 语义 | 例子 |
|------|------|------|
| `note` | 直觉（刷到时第一反应） | "这角度以前完全没想过。" |
| `observation` | 提炼（外部 AI 辅助后的总结） | "人物位置不特别，但低机位让建筑占据大量画面。" |
| `nextAttempt` | 行动（下次怎么试） | "下次拍环境人像时尝试一次低机位。" |
| `aiThread` | AI 对话线程 | 1.0 预留空数组，1.5 接入 AI 时写入 |

**1.0 外置 AI 的正面价值**：用户和外部 AI 聊完，要点要自己回填到 `observation`，这个回填动作本身就是提炼。新手成长靠提炼，不靠 AI 原话堆库。AI 原话塞多了，几年后回看会发现自己什么都没学到。

**1.5 接入 AI 时**：AI 输出也走 `observation` 字段，完整对话存 `aiThread`，语义无缝衔接。

## 五、1.0 数据结构

### PhotoNote

```
PhotoNote
├── id              // CloudBase 主键
├── imageUrl        // Storage 文件 URL
├── title           // 可选
├── note            // 直觉，可选
├── observation     // 提炼，可选
├── nextAttempt     // 行动，可选
├── source          // 来源，可选
├── tags[]          // 标签数组
├── aiThread[]      // AI 对话，1.0 预留空
├── writeToken      // 安全校验字段
├── createdAt       // 自动
└── updatedAt       // 自动
```

示例：

```json
{
  "title": "低机位让我重新认识环境人像",
  "note": "这个角度以前完全没想过。",
  "observation": "人物位置并不特别，但低机位让建筑占据大量画面。",
  "nextAttempt": "下次拍环境人像时尝试一次低机位。",
  "source": "Pinterest",
  "tags": ["低机位", "环境人像", "构图"],
  "aiThread": [],
  "writeToken": "<16位随机口令>"
}
```

**没有 User 表**。1.0 根本没有登录。

## 六、1.0 明确不做

以下功能不是不好，而是**现在都无法证明对核心需求有价值**。1.0 主动砍掉：

- 登录 / 注册 / 多用户
- 社交 / 评论 / 点赞
- AI 聊天 / AI 自动分析 / AI 标签
- 自动识别摄影师
- EXIF 分析 / RAW / 原图备份
- 手机 App Store 版本
- 分享社区 / 推荐算法 / 复杂统计
- 收藏夹嵌套 / 多级分类
- 语义搜索
- 分页（先用"最近 50 条不分页"够用）

## 七、用户体验流程

### 主流程（30 秒收藏）

1. 刷到照片（小红书 / Pinterest / 任意图源）
2. 截图
3. 打开摄影手册 PWA（手机桌面图标）
4. 点 `＋` 新增 → 上传截图 → 写一句直觉 → 标标签 → 保存
5. 30 秒内完成

### 深度流程（外部 AI 探讨，可选）

1. 收藏完一张照片后，想深入聊
2. 切到外部 AI（手机上的 ChatGPT / 豆包等），把照片和问题丢过去
3. AI 给出分析
4. 回到摄影手册，把要点回填到 `observation` 字段
5. 完整对话原文 1.0 不存（1.5 接入 AI 后会存 `aiThread`）

### 回看流程

- 首页按时间倒序翻
- 点标签按主题聚合（如 `#低机位`）
- 搜索框文本搜索
