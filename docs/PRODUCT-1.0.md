## 一、产品定位

**一句话概括：一本摄影参考手册。** 攒案例、标好档位和技巧，以后拍照前翻。

### 收录范围

**人像为主，但不是非得是人像。** 主线是看到喜欢的人像就存下来；别的好照片碰到了也能收。
它不是通用相册。

### 核心循环

**看到喜欢的照片 → 存下来 → AI 分析出拍摄档位和技巧 → 以后拍照时查阅参考。**

这个循环做到非常顺，是唯一的目标。

### 真正的产品价值

P5 是一个技术网站。收藏和分析都是手段，目的是给自己以后拍照提供参考。

所以分类和标签化是核心循环的一部分——不分类的话，积累的照片只是一条时间线，拍照时翻不到、对不上。

几年以后，准备拍环境人像时按「环境人像」筛出相关案例，想试低机位时筛出「仰拍」案例，
每张都带着 AI 分析出的档位和「下次这样拍」的技巧。这才是 P5 的价值。

---

## 二、核心原则

1. **视觉优先**：手机上大图、少文字。
2. **前期可以快记，内容要结构化**：收藏时先记一句话没问题，但从摄影角度来说不能停在"一句话"。维度档位才是参考库的价值所在——它由 AI 分析回填，不靠手打。不做"所有文字可选"的随记本。
3. **首页是视觉博客，不是后台管理界面**：按时间倒序的照片流，不是 Dashboard。
4. **私人项目，单账号门禁**：0.2 补了登录，但它是"门上的一把锁"，不是用户体系——不开放注册、不支持多用户，业务侧没有 User 表。账号由命令行创建。
5. **界面上一律只用「P5」**：不加副标题、不加 slogan。

## 三、功能范围

### 3.1 首页：照片流（已实现）

顶部只有名字和一个入口：

```
P5                                  ＋   筛选   ⋯
```

点 ＋ 新增；点「筛选」从顶栏下方展开抽屉面板，按维度筛选；点「⋯」退出登录。

下方按时间倒序显示案例。每条案例 = 一张照片 + 简短信息：

```
┌─────────────────────┐
│                     │
│       照片          │
│                     │
└─────────────────────┘

低机位让我重新认识环境人像

这个角度以前完全没想过。

2026.09.15
```

**不要**做复杂的卡片、统计图、Dashboard。

已补的交互：点照片全屏看（双指缩放、左右切换）；滚动时顶部条浮出下边界；**每张卡片右上角有 `×`**，二次确认后删掉这张（记录和桶里的文件一起删）。

0.14 起卡片带上两样东西（已实现），都在卡片内、不跳页：

```
┌─────────────────────────┐
│         照片            │
├─────────────────────────┤
│ 低机位让我重新认识环境人像   │
│ 中长焦 · 侧光 · 回眸 · 环境人像 │   ← 档位，只显示值
│ 2026.09.15     3 条技巧        │   ← 右侧条数，点了原地展开
└─────────────────────────┘
```

- **档位只显示值、不显示维度名**：一行塞不下 6 个「镜头:中长焦」，值本身够清楚；
  完整维度名在筛选区出现
- **「不确定」不上卡片**：它是 AI 拿不准时的合法出口，但没有任何参考价值——
  一行档位（含展开区）只留给真信息
- **技巧默认收起，只露条数**：3 条技巧占四行，默认展开会把首页从「看照片」变成
  「读文字」。但条数必须在，否则不知道这张值不值得点开
- **展开是原地展开**，不跳详情页（见 §3.3）。点「日期 + 条数」那一行切换：
  展开后是描述 + 全部档位（折行）+ 1-3 条技巧；没有技巧的照片同样可展开
  （右侧显示「展开 / 收起」），什么都没有的快记卡片不渲染这个开关
- 收起态档位超长时单行省略，展开区放开折行看全

原则是刷的时候轻、要看的时候一步展开就全有。

### 3.2 新增摄影案例（最重要的一页）

点首页右上角 `＋` 进入：

```
新增摄影案例

[ 上传照片 ]        ← 选完立即前端压缩，显示「3.2 MB → 420 KB」

标题                 (可选)
描述                 (可选)

档位                           ← 0.12：不再是手打标签，是 AI 回填的
  [ 生成提示词 ]   [ 粘贴回填 ]
  镜头    中长焦 ▾
  光线    侧光   ▾
  姿势    回眸   ▾
  （6 个基础维度 + AI 追加的，每一项都能改）

下次这样拍                      ← AI 给的，1-3 条
  · 站远一点、用长一点的焦段压缩背景
  · 让模特离背景再远些

[ 保存 ]
```

**关键设计**：前期可以先记一句话，但分类和标签才是参考库的核心——不是"所有文字可选"的随记本。

**已实现**：照片、标题、描述（`note`）、档位（含生成提示词 + 粘贴回填 + 人工确认）、AI 技巧。

**档位怎么来（0.10 定稿，0.12 / 0.13 落地）**：不是手打的，是 AI 分析回填的——这一页提供
「生成提示词」和「粘贴回填」两个动作，把剪贴板链路的两端接上（见 §3.5）。
0.12 先做能手选的那一版，0.13 再把 AI 回填叠上去（回填本质上就是自动点选同一套 chip）。

**维度不是录入的，是 AI 回填的**：这一页没有「加一个维度」这个动作，AI 返回什么就渲染什么。
但 AI 会判错，所以回填进来的每一项都能改 —— **改也只能在候选里挑**（值从该维度的字典里挑，
维度名从「6 个基础 + 库里已有的追加维度」里挑），**不给任何自由输入的框**。
理由见 §3.4：一旦自由发散，「中长焦」「长焦感」「长焦压缩」会同时存在，筛选就废了。

### 3.3 看一张照片（已实现，不另做详情页）

点一张照片 = 全屏看（双指缩放、左右切换），0.6 就是这样，**之后也不改成详情页**。

理由：标题、描述、档位、技巧在卡片上已经都看得到（技巧点一下原地展开）；
照片是主角，多一跳详情页只会稀释「点开就看」的爽感。
早期文档里的「案例详情页 + AI 分析按钮预留位」随这条决定一起砍掉。

### 3.4 维度档位（0.10 起，取代旧的自由标签）

标签不再是自由词，而是「**维度:值**」的技术属性。界面上看到的是 `中长焦`，
库里编码成 `镜头:中长焦`（编码方式的理由见 [ARCHITECTURE.md](ARCHITECTURE.md) §4.2）。

**6 个基础维度**，值只能从固定选项里选：

| 维度 | 值域 |
|------|------|
| 镜头 | 广角 / 标准 / 中长焦 / 长焦 / 不确定 |
| 时段 | 清晨 / 上午 / 正午 / 下午 / 黄昏 / 夜晚 / 室内恒定光 / 不确定 |
| 光线 | 顺光 / 侧光 / 逆光 / 顶光 / 柔光 / 硬光 / 不确定 |
| 视角 | 平视 / 仰拍 / 俯拍 / 不确定 |
| 景别 | 特写 / 近景 / 中景 / 全身 / 环境人像 / 不确定 |
| 姿势 | 面对镜头 / 侧身 / 回眸 / 行走 / 坐姿 / 倚靠 / 动态抓拍 / 不确定（可多选） |

**维度名放开（对 AI 放开），值收敛**——这是两层规则，别用一句话概括：

- **6 个之外，AI 可以自己开新维度**（如「道具」「场景」「色调」），维度和值都由它定。
  不可能一次想全，看到有价值的点就开一个。
  ⚠️ **维度不是人录入的**（2026-09-21 澄清）：新增页上没有任何「加一个维度」的输入动作，
  维度的产生只有 AI 返回这一条路。人在界面上只做修改 —— 改值（从该维度的候选里挑）、
  把不对的划掉。所以「道具」「小道具」「随身道具」并存这件事从根上不会发生
- **但同一个意思必须同一个写法**。要是「中长焦」「长焦感」「长焦压缩」并存，
  按值筛选就散了——而筛选正是这个库能不能用的前提。所以已用过的维度和值
  会在下次生成提示词时喂回给 AI，让它优先复用

**为什么是档位不是精确值**：从画面能判断「大致落在哪一档」（靠透视压缩、背景虚化形态），
判断不了「这支镜头 85mm」。所以值域写成区间，提示词里也明确禁掉 `85mm` 这类数字。
收藏的图基本都是手机截图，EXIF 早被平台剥掉了，没有精确来源。

**旧自由标签全部退役**：0.7–0.9 的「技法 6 个 + 题材 5 个」已在 0.10 清空
（迁移 `20260918180000_add_ai_tips_and_clear_tags.sql`），库里已有的 `tags` 一并清掉，**不迁移**
——两套体系并存会让筛选和探索区都要多处理一种情况。照片、标题、描述都不动。

首页「探索」区从标签云改成**按维度分组的分面筛选**（0.15，已实现）：
基础 6 个维度按字典顺序在前，AI 追加的维度按用量序接在后面；
维度内单选（点同维度的新值会替换旧值，再点一次取消），
跨维度可叠加（AND）—— 点「中长焦」看所有中长焦的案例，再点「逆光」看中长焦的逆光案例，
再点一次取消。这是最重要的学习路径——「我最近想练中长焦」，筛出来看一遍，
比按时间翻照片有价值得多。

0.19a 把筛选面板从首页常驻区收进**顶栏抽屉**：默认不占首屏，想查参考时一步展开。

### 3.5 AI 分析闭环（0.13）

**站里不接 AI**，用剪贴板人工中转——零后端成本，也没有密钥要管：

1. 新增页点「生成提示词」，复制
2. 连照片一起发给任意能看图的 AI
3. 把它回的 JSON 整段复制
4. 粘回新增页 → 解析 → 维度档位和技巧自动填好
5. **人工扫一眼确认** → 保存

**为什么用剪贴板而不是站内直连**：Cloud Function + API key 是一整套后端成本，
而这条链路对一个单人项目完全够用。将来 1.5 站内直连时用的是同一套维度字典和解析器，
差别只是把剪贴板换成函数调用——现在做不算弯路。

提示词正文（含全部设计理由）在 [PROMPT.md](PROMPT.md)，那是**措辞**的权威来源；
落到代码里是 `js/facets.js`（0.11），**值**的权威是那份文件里的 `BASE` 字典 ——
上面 6 个维度的值域、编码、提示词、校验都读它一处。

**第 5 步的人工确认不能省。** AI 会错，而错标签比没标签更坏——它会把参考库污染成
「你以为自己是中长焦拍的」。解析器分不清「光圈」和「道具」，所以拦截放在确认界面上，
由人一眼决定，不靠程序硬丢。

### 3.6 搜索（1.0，未开始）

做简单的文本搜索，匹配：标题、描述、维度值。

**不做** AI 语义搜索。等数据真的多了再考虑"找出所有和人物与环境关系有关的照片"这种语义检索。

### 3.7 视觉改版（0.16–0.18，已完成）

**起因（2026-09-23 用户反馈）**：现有冷灰底 + 磨砂玻璃 + 大圆角「灰灰的、很古早」，
字体排印平淡。0.6 定的那套是为「淡色 + 玻璃」服务的，放到 0.14 / 0.15 这类信息量下更显乱 ——
照片不再是主角。

**方向：规格手册感**（贴「一本摄影参考手册」这个定位）。
参照三处，各取一点：note.com 的编排与信息流、器材规格页的「标签—值」秩序、
Takram 的留白与字号层级。

**要解决的三件事**：

| # | 改什么 | 具体 |
|---|--------|------|
| 1 | **去灰** | 冷灰底 `#d7dbe2` → 暖白纸色；磨砂玻璃整套退场（`--glass` / `--blur` / `backdrop-filter` / `html::before` 光斑层），卡片改实色、细线或留白分隔 |
| 2 | **排印拉开层次** | 标题 16px / 500；档位行 13px；日期与计数 11px + 等宽数字（`tabular-nums`）；小节标签用大字距小字号；胶囊从满圆改小圆角矩形 |
| 3 | **布局** | 照片全出血（去掉左右内边距贴到屏幕边）；顶栏减负（「退出」收进菜单、「＋」轻量化）；探索区默认只展开前两组维度，「全部维度」展开 |

**拆法与归属**（照老规矩：一版一个交付、各自提交、各自验证）：

| 版本 | 内容 | 状态 |
|------|------|------|
| 0.16 | **基调**：`:root` 换暖白纸色、磨砂退场、排印层次 —— 三页共用一套 token | 已完成 |
| 0.17 | **首页布局**：照片全出血、顶栏减负、探索区默认折叠 | 已完成 |
| 0.18 | **其余页跟进**：新增页表单 / 上传区 / 档位胶囊、登录页对齐新基调 | 已完成 |

拆的顺序是先**基调**后**布局**：0.16 只动 `:root` 与文字相关规则，三页同时变；
0.17 只动首页的骨架（DOM 结构与内边距），两者互不干扰，各自能单独回退。
0.18 纯跟进，没有新决策。

**硬约束（改版里一条都不能破）**：

- 颜色只在 `:root` 一处，不许硬编码（`DESIGN.md` §一 有校验命令）
- 改配色后按**最坏情况重算对比度**（正文 ≥ 7:1、次要文字与按钮 ≥ 4.5:1）；
  0.6 改底色时 `--muted` / `--danger` 都掉到过不达标
- `css/style.css` 仍要排在 Vant `index.css` **之后**
- 无构建、无新依赖；Vant 只当控件用，卡片和顶栏的视觉自己写
- 0.6 时代的三条约定里，「照片是主角」保留，「不硬编码颜色」保留，
  「磨砂玻璃」随本次改版作废（`DESIGN.md` §二 整节在 0.16 里改写）

**不动的**：产品定位与收录范围；0.14 定的卡片信息层级；0.15 定的分面筛选语义
（维度内单选、跨维度叠加）；客户端聚合无云函数这条技术约束。

## 四、字段语义定义

| 字段 | 语义 | 例子 | 状态 |
|------|------|------|------|
| `title` | 标题 | "低机位让我重新认识环境人像" | 已实现 |
| `note` | 描述（自己写的） | "这个角度以前完全没想过。" | 已实现 |
| `tags` | 维度档位，值是 `维度:值` 编码 | `["镜头:中长焦", "光线:侧光"]` | 0.7 加列，0.10 清空旧值，0.12 起写入新语义 |
| `aiTips` | AI 给的「下次这样拍」 | `["站远一点、用长一点的焦段压缩背景"]` | 0.10 加列，0.13 起写入 |

`note` 和 `aiTips` 分开存、不合并：一是能分清哪句是自己写的、哪句是 AI 说的
（AI 会错，这个区分以后有用），二是将来让 AI 重新分析时，新技巧不会和旧的叠在一起。

## 五、数据结构

### 0.10 形态

```
PhotoNote
├── id            // 主键，自增
├── ownerId       // 归属人，取自登录身份，前端传不了
├── storagePath   // 私有桶内路径（不是 URL）
├── title         // 可选
├── note          // 描述，可选
├── tags          // 维度档位，写库前统一过 P5.cleanTags
├── aiTips        // AI 给的技巧数组，0.10 加
├── createdAt     // 自动
└── updatedAt     // 自动
```

示例：

```json
{
  "title": "低机位让我重新认识环境人像",
  "note": "这个角度以前完全没想过。",
  "tags": ["镜头:中长焦", "光线:侧光", "姿势:回眸", "景别:环境人像"],
  "aiTips": [
    "站远一点、用长一点的焦段压缩背景",
    "让模特离背景再远些，分离感会更强"
  ]
}
```

物理列名是 `snake_case`（`owner_id` / `storage_path` / `created_at` / `ai_tips`），前端 JS 里用 `camelCase`，在封装层做映射。

**业务侧没有 User 表**。0.2 加了登录，但那是身份门禁——账号由 CloudBase 身份服务托管，不产生业务数据表，也不支持多用户。照片的归属直接落在 `photo_notes.owner_id` 上。

**没有 `writeToken` 字段**。早期设计里有一版「用写入口令防盗刷」的方案，0.2 有登录后已放弃——口令在前端 JS 里人人可读，而登录身份伪造不了。详见 [ARCHITECTURE.md](ARCHITECTURE.md) §5.3。

## 六、明确不做

以下功能不是不好，而是**现在都无法证明对核心需求有价值**。主动砍掉：

- 注册 / 多用户（登录本身已在 0.2 补上，定位是单账号门禁）
- 社交 / 评论 / 点赞
- AI 聊天（站内不接 AI，分析走剪贴板把图发给外部 AI，见 §3.5）
- 自动识别摄影师
- **EXIF 读取** —— 收藏的图基本都是手机截图，EXIF 早被平台剥掉了。所以拍摄信息
  只能是 AI 从画面判断的**档位**，不会是精确的焦距 / 光圈 / 快门。哪天真有带 EXIF
  的图源再说
- RAW / 原图备份
- 手机 App Store 版本
- 分享社区 / 推荐算法 / 复杂统计
- 收藏夹嵌套 / 多级分类
- 语义搜索
- 编辑已保存的记录（**删除**已在 0.5 补上；改文字仍然不做——想改就删了重记）

## 七、用户体验流程

### 主流程（收藏）

1. 刷到喜欢的人像（小红书 / Pinterest / 任意图源）
2. 截图
3. 打开 P5（PWA 主屏图标待 1.0）
4. 点 `＋` 新增 → 选截图（自动压缩）→ 写一句描述
5. 点「生成提示词」复制 → 发给 AI → JSON 粘回 → 档位和技巧自动填好
6. 扫一眼确认（AI 可能判错）→ 保存

### 回看流程

- 首页按时间倒序翻（已实现）
- 按维度筛，如「中长焦」「逆光」（0.15）
- 卡片原地展开看技巧（0.14）
- 搜索框文本搜索（1.0）
