## 一、产品定位

### 核心循环

**收藏一张照片 → 写下自己的观察 → 以后重新看到它。**

这个循环做到非常顺，是唯一的目标。

### 真正的产品价值

不是"帮你收藏照片"。是几年以后，你打开 `#低机位` 看到 37 张，再打开 `#人物与环境` 看到 52 张，然后发现：

> "原来我一直喜欢这种构图。"

再过一段时间，你拍摄时会开始主动寻找这些东西。这才是 P5 真正的价值。

---

## 二、核心原则

1. **视觉优先**：手机上大图、少文字。
2. **所有文字可选**：刷到一张照片时可能只想记一句"这个角度以前完全没想过"，那也应该允许直接保存。不要用表单逼用户填完。
3. **首页是视觉博客，不是后台管理界面**：按时间倒序的照片流，不是 Dashboard。
4. **私人项目，单账号门禁**：0.2 补了登录，但它是"门上的一把锁"，不是用户体系——不开放注册、不支持多用户，业务侧没有 User 表。账号由命令行创建。
5. **界面上一律只用「P5」**：不加副标题、不加 slogan。

## 三、功能范围

### 3.1 首页：照片流（已实现）

顶部只有名字和一个入口：

```
P5                                  ＋
```

下方按时间倒序显示案例。每条案例 = 一张照片 + 简短信息：

```
┌─────────────────────┐
│                     │
│       照片          │
│                     │
└─────────────────────┘

低机位让我重新认识环境人像

这个角度以前完全没想过。

2026.09.15
```

**不要**做复杂的卡片、统计图、Dashboard。

已补的交互：点照片全屏看（双指缩放、左右切换）；滚动时顶部条浮出下边界；**每张卡片右上角有 `×`**，二次确认后删掉这张（记录和桶里的文件一起删）。

### 3.2 新增摄影案例（最重要的一页）

点首页右上角 `＋` 进入：

```
新增摄影案例

[ 上传照片 ]        ← 选完立即前端压缩，显示「3.2 MB → 420 KB」

标题                 (可选)
为什么               (可选，直觉)

[ 保存 ]
```

**关键设计**：所有文字字段都可选。允许只写一句"这个角度以前完全没想过"就保存。

**已实现**：照片、标题、为什么（`note`）。
**1.0 待补**：观察（`observation`）、下次尝试（`nextAttempt`）、标签（`tags`）、来源（`source`）。

### 3.3 案例详情（1.0）

点一条记录进入：

```
┌─────────────────────┐
│                     │
│       大照片        │
│                     │
└─────────────────────┘

这个低机位很有意思

2026.09.15

我的观察

人物的位置并不特别，但摄影机的位置很低，
导致建筑和天空占据了大量画面。

下次尝试

拍环境人像的时候，主动尝试一次低机位。

#低机位  #环境人像  #构图

来源
Pinterest
```

**预留位**：详情页留一个"AI 分析"按钮的位置，但 1.0 不实现。

### 3.4 标签（1.0）

预置标签（1.0 混用，1.5 拆维度）：

- **技法维度**：构图、角度、光线、色彩、姿势、镜头
- **题材维度**：环境人像、室内、夜景、街拍、场景

用户也可自建。

首页有"探索"区显示常用标签：

```
探索

#构图  #低机位  #逆光  #环境人像  #街拍
```

点击标签显示相关照片。这是未来非常重要的学习路径——"我最近想练低机位"，点 `#低机位` 看到所有收藏过的低机位照片，比按时间翻照片有价值得多。

### 3.5 搜索（1.0）

做简单的文本搜索，匹配：标题、note、observation、nextAttempt、tags。

**不做** AI 语义搜索。等数据真的多了再考虑"找出所有和人物与环境关系有关的照片"这种语义检索。

## 四、字段语义定义

| 字段 | 语义 | 例子 | 状态 |
|------|------|------|------|
| `title` | 标题 | "低机位让我重新认识环境人像" | 已实现 |
| `note` | 直觉（刷到时第一反应） | "这角度以前完全没想过。" | 已实现 |
| `observation` | 提炼（外部 AI 辅助后的总结） | "人物位置不特别，但低机位让建筑占据大量画面。" | 1.0 |
| `nextAttempt` | 行动（下次怎么试） | "下次拍环境人像时尝试一次低机位。" | 1.0 |
| `source` | 来源 | "Pinterest" | 1.0 |
| `tags` | 标签数组 | `["低机位", "环境人像"]` | 1.0 |
| `aiThread` | AI 对话线程 | 预留空数组，1.5 接入 AI 时写入 | 1.5 |

**1.0 外置 AI 的正面价值**：用户和外部 AI 聊完，要点要自己回填到 `observation`，这个回填动作本身就是提炼。新手成长靠提炼，不靠 AI 原话堆库。AI 原话塞多了，几年后回看会发现自己什么都没学到。

**1.5 接入 AI 时**：AI 输出也走 `observation` 字段，完整对话存 `aiThread`，语义无缝衔接。

## 五、数据结构

### 已实现（0.3）

```
PhotoNote
├── id            // 主键，自增
├── ownerId       // 归属人，取自登录身份，前端传不了
├── storagePath   // 私有桶内路径（不是 URL）
├── title         // 可选
├── note          // 直觉，可选
├── createdAt     // 自动
└── updatedAt     // 自动
```

物理列名是 `snake_case`（`owner_id` / `storage_path` / `created_at`），前端 JS 里用 `camelCase`，在封装层做映射。

### 1.0 待补

```
├── observation   // 提炼，可选
├── nextAttempt   // 行动，可选
├── source        // 来源，可选
├── tags[]        // 标签数组
└── aiThread[]    // AI 对话，1.0 预留空，1.5 写入
```

示例（1.0 形态）：

```json
{
  "title": "低机位让我重新认识环境人像",
  "note": "这个角度以前完全没想过。",
  "observation": "人物位置并不特别，但低机位让建筑占据大量画面。",
  "nextAttempt": "下次拍环境人像时尝试一次低机位。",
  "source": "Pinterest",
  "tags": ["低机位", "环境人像", "构图"],
  "aiThread": []
}
```

**业务侧没有 User 表**。0.2 加了登录，但那是身份门禁——账号由 CloudBase 身份服务托管，不产生业务数据表，也不支持多用户。照片的归属直接落在 `photo_notes.owner_id` 上。

**没有 `writeToken` 字段**。早期设计里有一版「用写入口令防盗刷」的方案，0.2 有登录后已放弃——口令在前端 JS 里人人可读，而登录身份伪造不了。详见 [ARCHITECTURE.md](ARCHITECTURE.md) §5.3。

## 六、明确不做

以下功能不是不好，而是**现在都无法证明对核心需求有价值**。主动砍掉：

- 注册 / 多用户（登录本身已在 0.2 补上，定位是单账号门禁）
- 社交 / 评论 / 点赞
- AI 聊天 / AI 自动分析 / AI 标签
- 自动识别摄影师
- EXIF 分析 / RAW / 原图备份
- 手机 App Store 版本
- 分享社区 / 推荐算法 / 复杂统计
- 收藏夹嵌套 / 多级分类
- 语义搜索
- 分页（先用"最近 50 条不分页"够用）
- 编辑已保存的记录（**删除**已在 0.5 补上；改文字仍然不做——想改就删了重记）

## 七、用户体验流程

### 主流程（30 秒收藏）

1. 刷到照片（小红书 / Pinterest / 任意图源）
2. 截图
3. 打开 P5（本地 HTTP 服务或已配置的站点，PWA 主屏图标待 1.0）
4. 点 `＋` 新增 → 选截图（自动压缩）→ 写一句直觉 → 保存
5. 30 秒内完成

### 深度流程（外部 AI 探讨，可选）

1. 收藏完一张照片后，想深入聊
2. 切到外部 AI（手机上的 ChatGPT / 豆包等），把照片和问题丢过去
3. AI 给出分析
4. 回到 P5，把要点回填到 `observation` 字段（1.0 有这栏之后）
5. 完整对话原文 1.0 不存（1.5 接入 AI 后会存 `aiThread`）

### 回看流程

- 首页按时间倒序翻（已实现）
- 点标签按主题聚合，如 `#低机位`（1.0）
- 搜索框文本搜索（1.0）
