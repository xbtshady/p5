## 一、产品定位

### 核心循环

**收藏一张照片 → 记下描述 → 分类标签化 → 以后拍照时查阅参考。**

这个循环做到非常顺，是唯一的目标。

### 真正的产品价值

P5 是一个技术网站。收藏和记描述是手段，目的是给自己以后拍照提供参考。

所以分类和标签化是核心循环的一部分——不分类的话，积累的照片只是一条时间线，拍照时翻不到、对不上。

几年以后，准备拍环境人像时打开 `#环境人像` 看到相关案例，想试低机位时打开 `#低机位` 看到相关案例，每张都带着当时记下的描述。这才是 P5 的价值。

---

## 二、核心原则

1. **视觉优先**：手机上大图、少文字。
2. **前期可以快记，内容要结构化**：收藏时先记一句话没问题，但从摄影角度来说不能停在"一句话"。分类和标签才是参考库的价值所在。不做"所有文字可选"的随记本。
3. **首页是视觉博客，不是后台管理界面**：按时间倒序的照片流，不是 Dashboard。
4. **私人项目，单账号门禁**：0.2 补了登录，但它是"门上的一把锁"，不是用户体系——不开放注册、不支持多用户，业务侧没有 User 表。账号由命令行创建。
5. **界面上一律只用「P5」**：不加副标题、不加 slogan。

## 三、功能范围

### 3.1 首页：照片流（已实现）

顶部只有名字和一个入口：

```
P5                                  ＋
```

下方按时间倒序显示案例。每条案例 = 一张照片 + 简短信息：

```
┌─────────────────────┐
│                     │
│       照片          │
│                     │
└─────────────────────┘

低机位让我重新认识环境人像

这个角度以前完全没想过。

2026.09.15
```

**不要**做复杂的卡片、统计图、Dashboard。

已补的交互：点照片全屏看（双指缩放、左右切换）；滚动时顶部条浮出下边界；**每张卡片右上角有 `×`**，二次确认后删掉这张（记录和桶里的文件一起删）。

### 3.2 新增摄影案例（最重要的一页）

点首页右上角 `＋` 进入：

```
新增摄影案例

[ 上传照片 ]        ← 选完立即前端压缩，显示「3.2 MB → 420 KB」

标题                 (可选)
描述                 (可选)

[ 保存 ]
```

**关键设计**：前期可以先记一句话，但分类和标签才是参考库的核心——不是"所有文字可选"的随记本。

**已实现**：照片、标题、描述（`note`）、标签（`tags`，0.8）。

**标签怎么填（0.8 定稿）**：预置清单点选为主、自定义输入为辅。预置分两组（见 §3.4），
选中的原地高亮；清单里没有的走输入框，支持一次打「低机位, 仰拍」切成多个。
**为什么要预置**：标签一旦自由发散，「低机位」「低角度」「仰拍」会同时存在，
三个标签指同一件事——参考库最怕这个，翻的时候对不上。输入的内容自动归并：
打「构图」时如果预置里已有，就点亮那个预置项，不重复造一个自定义。

### 3.3 看一张照片（已实现，不另做详情页）

点一张照片 = 全屏看（双指缩放、左右切换），0.6 就是这样，**1.0 也不改成详情页**。

理由：标题、描述、标签在卡片上已经都看得到；照片是主角，多一跳详情页只会
稀释「点开就看」的爽感。早期文档里的「案例详情页 + AI 分析按钮预留位」随这条决定一起砍掉，
1.5 接 AI 时再决定入口放哪。

### 3.4 标签（已实现，0.7–0.9）

预置标签（1.0 混用，1.5 拆维度）：

- **技法维度**：构图、角度、光线、色彩、姿势、镜头
- **题材维度**：环境人像、室内、夜景、街拍、场景

用户也可自建（单标签最多 12 字、一张照片最多 6 个）。

首页有"探索"区显示常用标签（带各自的照片数，按用量倒序）：

```
探索

#构图 2   #低机位 2   #环境人像 1   #逆光 1
```

点标签按该标签筛选当前列表，再点一次取消；卡片上的标签点一下也是同一个动作。
这是未来非常重要的学习路径——"我最近想练低机位"，点 `#低机位` 看到所有收藏过的
低机位照片，比按时间翻照片有价值得多。

### 3.5 搜索（1.0，未开始）

做简单的文本搜索，匹配：标题、描述、标签。

**不做** AI 语义搜索。等数据真的多了再考虑"找出所有和人物与环境关系有关的照片"这种语义检索。

## 五、数据结构

### 已实现（0.7 全部就位）

```
PhotoNote
├── id            // 主键，自增
├── ownerId       // 归属人，取自登录身份，前端传不了
├── storagePath   // 私有桶内路径（不是 URL）
├── title         // 可选
├── note          // 描述，可选
├── tags          // 标签数组，写库前统一过 P5.cleanTags
├── createdAt     // 自动
└── updatedAt     // 自动
```

示例：

```json
{
  "title": "低机位让我重新认识环境人像",
  "note": "这个角度以前完全没想过。",
  "tags": ["低机位", "环境人像", "构图"]
}
```

物理列名是 `snake_case`（`owner_id` / `storage_path` / `created_at`），前端 JS 里用 `camelCase`，在封装层做映射。

**业务侧没有 User 表**。0.2 加了登录，但那是身份门禁——账号由 CloudBase 身份服务托管，不产生业务数据表，也不支持多用户。照片的归属直接落在 `photo_notes.owner_id` 上。

**没有 `writeToken` 字段**。早期设计里有一版「用写入口令防盗刷」的方案，0.2 有登录后已放弃——口令在前端 JS 里人人可读，而登录身份伪造不了。详见 [ARCHITECTURE.md](ARCHITECTURE.md) §5.3。

## 六、明确不做

以下功能不是不好，而是**现在都无法证明对核心需求有价值**。主动砍掉：

- 注册 / 多用户（登录本身已在 0.2 补上，定位是单账号门禁）
- 社交 / 评论 / 点赞
- AI 聊天 / AI 自动分析 / AI 标签
- 自动识别摄影师
- EXIF 分析 / RAW / 原图备份
- 手机 App Store 版本
- 分享社区 / 推荐算法 / 复杂统计
- 收藏夹嵌套 / 多级分类
- 语义搜索
- 分页（先用"最近 50 条不分页"够用）
- 编辑已保存的记录（**删除**已在 0.5 补上；改文字仍然不做——想改就删了重记）

## 七、用户体验流程

### 主流程（30 秒收藏）

1. 刷到照片（小红书 / Pinterest / 任意图源）
2. 截图
3. 打开 P5（本地 HTTP 服务或已配置的站点，PWA 主屏图标待 1.0）
4. 点 `＋` 新增 → 选截图（自动压缩）→ 写一句描述 → 点几个标签 → 保存
5. 30 秒内完成

### 回看流程

- 首页按时间倒序翻（已实现）
- 点标签按主题聚合，如 `#低机位`（已实现，0.9）
- 搜索框文本搜索（1.0）
