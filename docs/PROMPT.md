# 照片分析提示词

版本：0.11
最后更新：2026-09-21

发给外部 AI 的一段提示词。**贴一张照片 + 下面这段，AI 回一段 JSON，粘回新增页就能自动填好维度标签。**

## 工作流

1. 复制下面的提示词，连同照片一起发给任意能看图的 AI
2. 把回你的 JSON 整段复制
3. 粘回新增页的标签区，确认后保存

站里不接 AI，靠剪贴板人工中转 —— 零后端成本，也没有密钥要管。
将来 1.5 站内直连时用的还是同一套字典和解析器，差别只是把剪贴板换成函数调用。

> 📌 **「已有维度」那一节现在是占位。** 库里还没积累任何维度，手动复制时
> **把那一节连同下面三行整段删掉**。将来站内「生成提示词」按钮会自动拼上真实内容，
> 库为空时这一节不会出现（见文末「与代码的关系」）。

## 提示词

```
你是摄影技术分析助手（多为人像）。我会发给你一张照片，请判断它是怎么拍出来的。

我建这个库是为了以后拍照时查参考。我要的是**能复用到别的照片上的属性 / 技术特征**，
不是对这张照片的文字描述：

  可以：中长焦 / 逆光 / 回眸 / 透明雨伞 —— 别的照片也可能出现
  不行：她在笑 / 海边的傍晚 / 氛围温馨 —— 只属于这一张，或者根本没法用来筛选

【必答的 6 个维度】值只从列出的选项里选
（我要靠这些值筛选照片，同一个意思写成两个词就散架了）

镜头：广角（<35mm） / 标准（35–70mm） / 中长焦（70–135mm） / 长焦（>135mm） / 不确定
时段：清晨 / 上午 / 正午 / 下午 / 黄昏 / 夜晚 / 室内恒定光 / 不确定
光线：顺光 / 侧光 / 逆光 / 顶光 / 柔光 / 硬光 / 不确定
视角：平视 / 仰拍 / 俯拍 / 不确定
景别：特写 / 近景 / 中景 / 全身 / 环境人像 / 不确定
姿势：面对镜头 / 侧身 / 回眸 / 行走 / 坐姿 / 倚靠 / 动态抓拍 / 不确定（可多选，用「/」隔开）

【已有维度，优先复用】
下面是我库里已经用过的维度（6 个基础维度之外的）。
**能对上的就沿用原来的写法**，不要为同一个意思造一个新词 —— 那会让我筛不到一起。

道具：透明雨伞 / 反光板
场景：老街 / 咖啡馆
色调：低饱和 / 冷调

【其他技术点：你自己开新维度】
确实出现了上面没有、又对我以后拍照有参考价值的技术点，才新建维度 ——
优先复用已有的，没有合适的再新增。维度和值都由你定，要求：
维度名用简短名词（如「道具」「场景」「色调」），值要能复用到别的照片上。

⚠️ 不要为了用上某个已有维度而硬套，只填你在这张照片里确实看到的。

【再给我 1-3 条 tips】
说明「下次想拍出类似效果，我需要注意什么」。
每条都要具体可操作，不要写「注意光线」这种空话。

【规矩】
- 拿不准就选「不确定」，不要硬猜，宁可空着也别编。
- 单张照片无法可靠推断的精确拍摄参数（如精确焦距、光圈、快门、具体钟点），
  不要猜测，也不要为了填写完整而新增这些参数维度；无法可靠判断就不输出。
- 每个判断附一句依据，15 字以内。

【输出】
只输出 JSON，不要解释文字，不要代码围栏：

{
  "facets": {
    "镜头": {"v": "中长焦", "why": "背景压缩明显"},
    "时段": {"v": "下午", "why": "影子偏长"},
    "光线": {"v": "侧光", "why": "面部明暗各半"},
    "视角": {"v": "平视", "why": "相机与眼睛齐平"},
    "景别": {"v": "环境人像", "why": "人物约占画面三分之一"},
    "姿势": {"v": "回眸", "why": "身体背向、头回转"},
    "道具": {"v": "透明雨伞", "why": "逆光下成了亮点"}
  },
  "tips": [
    "站远一点、用长一点的焦段压缩背景",
    "让模特离背景再远些，分离感会更强",
    "逆光时测光点压在脸上，不然脸会黑"
  ]
}
```

## 为什么这么写

**首句不写死「人像」。**
收录范围是「人像为主，但不是非得是人像」（PRODUCT §一）。首句若写「你是人像摄影技术分析助手。
我会发给你一张人像照片」，非人像照片发进去会被暗示往人像的框里套 —— 所以放宽成
「摄影技术分析助手（多为人像）」+「一张照片」。

6 个基础维度**不跟着动**：镜头 / 时段 / 光线 / 视角 / 景别对非人像同样成立，只有「姿势」
可能不适用，走已有的「不确定」出口就行。不为少数情况加一节特例规则 —— 那会让主路径（人像）
多背一层分支，而分支正是后面解析器容易出错的地方。

**不写判断方法。**
「按色温和影子长短判断」这种话是多余的 —— AI 看图判断压缩感、色温、影子本来就会，
写进去只会稀释注意力，还可能让它机械套那几个词去凑答案。
要写的只有 AI 不知道的东西：我的词汇表、输出格式、边界规则。

**值收敛，维度放开。**
这是两层规则，约束的不是同一个东西：

- **值**必须从选项里选。因为要按值筛选照片，「中长焦」「长焦感」「长焦压缩」
  三个词指一件事，探索区就散了。
- **维度名**归 AI 自己定。不可能一次想全，看到有价值的点就开一个。

⚠️ 不要写成一句「不要自己造词」概括掉。那和「可以自己追加维度」自相矛盾，
AI 会优先守禁令，追加那段就彻底成了摆设。

**必须给「不确定」这个出口。**
不给，AI 宁可编一个也不愿空着。而错标签比没标签更坏 ——
它会把参考库污染成「你以为自己是 85mm 拍的」。

能推断的和不能推断的界线要划清楚：透视压缩、色温、影子、景别这些**档位**看得见；
精确焦距、光圈、快门、具体钟点看不见（EXIF 在压缩那一步就丢了）。
所以规矩里单列一条：**不要猜、也不要为了「填得完整」新增这类维度，判断不了就不输出。**

这里有个必须写死的区别：**档位可以给，精确值不可以。**「中长焦」是从画面推出来的，
「85mm」是编的 —— AI 很容易把后者当成「说得更具体」，所以要明确挡掉。
「不要为了填得完整而新增维度」这半句尤其不能省：前面允许了 AI 自由开新维度，
它完全可能自己造一个「光圈：f/2.8」出来，而那个数只能靠猜。

⚠️ 拦截放在**人工确认**那一关，不靠解析器硬丢。解析器分不清「光圈」和「道具」，
一刀切会把真正有价值的追加维度一起杀掉。AI 若真给了这类参数，它会落在回填界面的
「AI 补充」区里、标着是 AI 新增的，删不删由人看一眼决定。

**镜头那栏给的是档位，不是精确值。**
从透视压缩、主体与背景分离程度、背景虚化形态判断**大致落在哪个档**是可行的，
判精确焦距不可行。所以选项写成区间、输出只要档名。

**tips 是给下次拍摄用的，不是「AI 为什么这么分类」。**
所以要求 1-3 条、要具体可操作，并挡掉「注意光线」这类空话 ——
一条挤不下就写两条，硬合成一句反而容易变成废话。

**「已有维度」那节要连值一起给，不能只给维度名。**
只给维度名，复用就只到「维度」这一层：AI 知道该用「道具」，但可能这次写
「透明雨伞」、下次写「雨伞」、再下次写「长柄伞」—— 同义词问题一点没解决，
而这个问题正是这个池子存在的唯一理由。

**池子会诱导 AI 硬套。**
一张已有值列表本身就是 few-shot 提示，AI 的天性是「把这些词用上」。
所以旁边必须写一句「不要为了用上某个已有维度而硬套，只填你确实看到的」，
否则它会每张照片都塞一个「道具」。

**池子只列 6 个基础维度之外的。**
基础维度的值域上面已经写死了，重复列一遍是浪费字号，还容易让两处说法漂移。

**示例里故意带了一项「道具」。**
示例要让 AI 看见「追加维度」长什么样，否则它只会照着 6 个基础维度抄一遍。

**要求只输出 JSON，但解析器仍要容错。**
剥代码围栏、tips 给成字符串、**缺了某个维度就当没给（不报错）**、
值不在枚举里降级成自定义值（不丢弃）、实在解析不出来就把原文贴回给人看，不静默吞掉。

## 与代码的关系

**这份文本已经落在 `js/facets.js` 里（0.11 完成）**，站内「生成提示词」按钮输出的就是它 ——
按钮本身 0.13 才接上，在那之前只能手动复制。

> **值是 `BASE` 字典的权威，措辞是这份文档的权威。**
> 上面代码块里的 6 行维度（值域 + 口径说明 + 多值写法）由 `facets.js` 的 `BASE` **渲染**出来，
> 不是手写的 —— 提示词里的值域必须和界面能选的完全一样，手抄两份迟早漂。
> 改值改 `BASE`，改措辞改这份文档，然后把两边对齐。

- 上面代码块是**「带池子」的版本**（池子举的是示例值 道具 / 场景 / 色调）。
  `buildPrompt(tags)` 生成时池子从库里真实 tags 聚合（`poolFromTags`），
  只取**非基础维度**的维度名 + 各自用过的值
- 「已有维度」那节**不在模板里写死**。池子为空时，整节连同后面那句「别硬套」一起不出现
  （不能留个空标题让 AI 困惑）。现在库里维度还是空的，所以线上看到的是没有这一节的版本
- 待观察：池子大了会稀释注意力，届时按使用频率截断（每个维度只带最常用的几个值）
- 回填解析器也在同一个文件（`parseReply`），容错规则见上面「为什么这么写」里最后一条
- ⚠️ **冒号是保留字符**（`维度:值` 的编码分隔符），值里绝不能有冒号 ——
  `encode()` 会直接拒绝这种值。同一份禁用字符清单在 `facets.js` 的 `RESERVED` 里，
  和 `cloudbase.js` 的 `TAG_STRIP` 是一套理由（SDK 拼查询不转义）
