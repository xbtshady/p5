## 一、为什么要再重构

0.16–0.18 已经把「规格手册感」的基调落到了线上，但对着真实渲染再看，
还有 8 个影响「刷」和「查」的问题没有解决。下面是基于无头 Chrome 实际截图（390px 宽度）的逐项诊断。

| # | 问题 | 当前截图里的表现 | 导致的后果 |
|---|------|----------------|-----------|
| 1 | **探索区喧宾夺主** | 首页首屏被「探索」标题 + 两组维度胶囊 + 「全部 6 组维度」按钮占掉约 180px | 打开 App 第一眼看不到照片，违背「首页是照片流」的定位 |
| 2 | **顶栏操作按钮看不清** | 「＋」和「⋯」是 30×30 白底 + 浅灰边，在 `#fbfaf8` 底色上几乎融入背景 | 用户找不到新增入口，退出这类低频操作反而占了一个常驻图标 |
| 3 | **卡片内文字对齐混乱** | 照片全出血到屏幕边，标题/档位/日期却缩进 18px | 照片像「贴上去的」，文字块像「浮在照片下面」，不像一个整体 |
| 4 | **展开操作区域太小** | 「2 条技巧」开关只有 11px 字 + 4px 内边距 | 单手很难点中，用户可能根本不知道能展开 |
| 5 | **日期与技巧开关抢同一行** | 日期左对齐，「n 条技巧」右对齐，两者信息量不对等却并排 | 视觉重心分散，用户不知道点哪里 |
| 6 | **新增页像设置面板** | 6 组维度胶囊垂直铺开，占满整个屏幕 | 录入一张照片像在填一份长问卷，心理负担大 |
| 7 | **保存按钮淹没在长表单里** | 保存按钮在最底部，前面是 AI 提示词、档位、tips | 用户要滑到底才能保存，打断「快记」节奏 |
| 8 | **整体缺少「参考手册」的秩序感** | 只有字号和灰度区分，没有明确的「页眉 / 章节 / 条目」层级 | 看起来像一个普通笔记 App，不像能查资料的手册 |

核心结论：**0.18 完成了「去灰去磨砂」，但还没完成「把参考手册的信息结构做出来」。**

---

## 二、重构目标

不推翻 0.18 的基调（暖白纸色、中性色、照片唯一彩色、小圆角），只重新组织信息。

1. **首页默认只看照片** —— 把「探索」从常驻区移走，需要查的时候一步展开。
2. **单手操作优先** —— 所有可交互元素最小 40×40 CSS px，文字按钮不小于 13px。
3. **卡片像一张索引卡** —— 照片 + 标题 + 元信息 + 可展开详情，四个区域边界清楚。
4. **新增页像填一张卡片，不像填一份问卷** —— 分组、可折叠、保存触手可及。
5. **保持无构建、无新依赖** —— 继续用 Vue 3 CDN + Vant 4 + 原生 CSS。

## 三、信息架构与布局方案

### 3.1 首页：把「探索」收进顶栏抽屉

```
┌──────────────────────┐
│ P5        ＋   筛选   ⋯ │   ← 顶栏：新增、筛选、更多（退出）
├──────────────────────┤
│                      │
│        照片 1        │
│                      │
│ 标题                 │
│ 中长焦 · 逆光 · 黄昏   │
│ 2026.09.21  ·  2 条  │   ← 点整行展开
│                      │
│        照片 2        │
│                      │
└──────────────────────┘
```

**改动点：**

- 移除首页顶部常驻的「探索」面板。
- 顶栏右侧三个动作：「＋」（新增）、「筛选」（漏斗图标）、「⋯」（退出）。
- 点击「筛选」后，从顶栏下方滑下一个全宽筛选面板（不是新页），面板内包含原来的维度分组 + 清除按钮 + 关闭按钮。
- 面板关闭后，首页回到纯照片流。
- 有筛选生效时，顶栏「筛选」图标加一个小红点或文字徽标；同时 feed 顶部出现一行「只看 中长焦 + 逆光  ·  清除」的提示条。

**为什么这样：**

- 用户 80% 的访问可能是「刷最近的照片」，不应该每次都被探索区顶到首屏外。
- 查参考时，筛选是一个明确的「进入搜索模式」动作，抽屉面板能提供足够空间。
- 不引入新路由或新页面，纯前端状态切换，后台不用改。

### 3.2 照片卡片：做成「索引卡」

```
┌──────────────────────┐
│                      │
│        照片          │   ← 全出血保留
│                      │
├──────────────────────┤
│ 地铁口的逆光侧脸      │   ← 标题 16px / 500
│ 中长焦 · 逆光 · 黄昏  │   ← 档位 13px / muted
│ 2026.09.21   ·   查看 │   ← 日期 + 展开触发，整行可点
├──────────────────────┤   ← 展开后：上边框 1px 细节线
│ 描述                 │
│ 镜头：中长焦          │
│ 光线：逆光            │
│ - 让人物偏离中心...   │
│ - 按人脸测光...       │
└──────────────────────┘
```

**改动点：**

- 照片仍然全出血，但卡片下方的信息区也改为**全宽白底块**，和照片之间用 1px 细节线分开（或者照片底部直接压住白底块，类似杂志 caption）。
- 标题、档位、日期行统一左对齐到 16px（或 18px）内边距，不再出现「照片到边、文字缩进」的错位。
- **展开触发区做成整行可点**（日期 +「查看 / 收起」），而不是只有一个 11px 小按钮。最小点击高度 40px。
- 展开后内容用 1px 细节线与默认区隔开，而不是目前的 `padding-top` 留白。
- 删除按钮从照片右上角移到底部操作行，或者保留但加大到 36×36 并提升对比。
- 卡片间距从 38px 缩小到 28px，让 feed 更紧凑；卡片之间用 1px 细节线或者纯留白区分，二选一。

**保留不变：**

- 不做详情页。
- 技巧默认收起，默认态档位只显示值。
- 不确定档位不上卡片。

### 3.3 新增页：分组 + 可折叠 + 底部固定保存

```
┌──────────────────────┐
│ ←  P5                │
├──────────────────────┤
│ 照片                 │
│ [   上传占位   ]     │
│                      │
│ 标题 / 描述          │   ← 可折叠组（默认展开）
│ [ 生成提示词并复制 ] │
│ [ 粘贴框：粘上就填 ] │   ← 生成之后才出现
│                      │
│ 档位           [展开]│   ← 可折叠组（默认折叠）
│   镜头      长焦压缩 │   ← 整行可点
│   [广角 标准 中长焦…]│   ← 点开后在行下面展开
│   时段          下午 │
│   光线          逆光 │
│                      │
│ AI 技巧        [展开]│   ← 可折叠组（默认折叠）
│                      │
│ ┌──────────────────┐ │
│ │      保 存       │ │   ← 底部固定保存条
│ └──────────────────┘ │
└──────────────────────┘
```

**改动点：**

- 页面拆成 3 个可折叠分组：
  1. **基本信息**（照片、标题、描述）—— 默认展开；
  2. **档位**（AI 回填/手选维度）—— 默认折叠，点击展开；
  3. **AI 技巧** —— 默认折叠，点击展开。
- 折叠组头部显示当前已选摘要，例如「档位：中长焦 / 逆光 / 侧身」，让用户不用展开也知道填了什么。
- 档位组内，**单选维度一行一个**，点开后在行下面展开候选值；只有多选维度（姿势）和 AI 追加维度保留平铺胶囊。
  - 理由：镜头/时段/光线/视角/景别这 5 个维度每次只能选一个值，把 25 个胶囊全平铺出来既撑长首屏，找值也慢。
  - ⚠️ 0.19c 把它实现成了底部弹层（`van-picker`），**0.19d 已改回行内展开** —— 弹层要「点行 → 滚轮 → 点确认」三下，而一维只选一个值本该两下完事，遮罩还会把维度名和已选值一起挡掉。见 §十四。
- AI 那一段只有**一颗**主按钮（生成提示词并复制）：点它 = 复制 + 露出粘贴框，粘贴由 `onPaste` 接管并自动回填。放在基本信息组底部，而不是顶栏下面。
- 保存按钮固定在底部工具栏（sticky footer），不随表单滚动消失。
- 返回按钮从文字改成左箭头图标，与 iOS/Android 惯例一致。

**保留不变：**

- 仍然不走 AI 直连，仍然用剪贴板中转。
- 维度值仍然只能从字典/池子挑，不给自由输入。

### 3.4 登录页：居中卡片保留，增强品牌

- 保持居中卡片布局，这是登录页最合适的结构。
- 品牌区「P5」字号从 20px 稍微放大并加字距，让它一眼就是这个应用。
- 输入框标签从占位符式改成顶部小标签（floating label 或固定小标签），提升可读性。
- 登录按钮保持主色填满，不再用 Vant 默认样式。

### 3.5 顶栏统一处理

三页共用 `.topbar`，但内容不同：

| 页面 | 左侧 | 中间 | 右侧 |
|------|------|------|------|
| 首页 | （无，P5 可居中或左对齐） | P5 | ＋、筛选、⋯ |
| 新增 | ← 返回图标 | P5 | （空） |
| 登录 | （无） | P5 | （空） |

- **动作按钮全部填充/加深**：
  - 「＋」做成 32×32 近黑底 + 白字「＋」，高对比。
  - 「筛选」用图标 + 文字（或纯图标），当前有筛选时显示红点/徽标。
  - 「⋯」改成头像/菜单图标，打开后是「退出登录」。
- 顶栏滚动后仍保留 1px 下边界，但可以考虑在首页默认态下边界隐藏，滚动才出现（目前已经是这样）。

## 四、视觉与排印规范（细化，不推翻）

### 4.1 颜色：继续用 0.18 这套

```css
--bg: #fbfaf8;
--card: #ffffff;
--text: #17181a;
--muted: #6b6f76;
--accent: #17181a;
--danger: #b3382a;
--border: var(--ink-10);
```

颜色足够，不需要引入新彩色。重点是**用法**改变：

- 卡片/面板用 `--card` 纯白，和 `--bg` 纸白形成层；
- 分隔用 `--border` 1px 细节线；
- 主操作按钮用 `--accent` 填满；
- 文字按钮/图标默认 `--text`，hover 用 `--muted` 背景。

### 4.2 字号与字重

| 层级 | 字号 | 字重 | 用途 |
|------|------|------|------|
| 品牌 | 20px | 500 | 顶栏 P5 / 登录页品牌 |
| 标题 | 16px | 500 | 卡片标题、分组标题 |
| 正文 | 14px | 400 | 描述、tips、输入文字 |
| 元信息 | 12px | 400 | 日期、档位行 |
| 小节标签 | 11px | 500 | 维度组名、计数 |

**改动：**

- 卡片描述从 13px 提到 14px，可读性更好。
- 日期和档位明确用 12px，和 16px 标题拉开。
- 小节标签 11px 保留，但加字距。

### 4.3 间距系统

把目前散落的间距收进几个变量：

```css
--gutter: 16px;          /* 页面左右留白 */
--section-gap: 32px;     /* 分组之间 */
--card-gap: 24px;        /* 卡片之间 */
--touch-min: 44px;       /* 可点区域最小高度 */
```

首页卡片之间 24px，不再用 38px。

### 4.4 圆角

- 按钮 / 胶囊：6px
- 卡片 / 面板：8px
- 输入框：6px
- 顶部抽屉面板：底部圆角 12px（滑出感）

### 4.5 动效

- 筛选抽屉滑入：200ms ease-out；
- 折叠组展开：高度 200ms，内容淡入 150ms；
- 卡片展开：不位移，只展开内容，避免列表跳动；
- 保持 `prefers-reduced-motion` 尊重。

## 五、关键交互细节

### 5.1 筛选抽屉

- 默认收起；点击顶栏「筛选」后从顶栏下方滑出，覆盖内容区上半部分或全屏。
- 抽屉内分组与当前 0.15 一致：基础维度在前，AI 追加维度在后。
- 抽屉关闭按钮放在抽屉顶部右侧，同时点遮罩或按 Esc 关闭。
- 有筛选生效时，feed 顶部出现一行「只看 …  ·  清除」提示条，点击清除关闭筛选并隐藏提示条。
- 维度内单选、跨维度叠加的语义保持 0.15 不变。

### 5.2 卡片展开

- 默认态：标题 + 档位行 + 日期行（整行可点）。
- 展开后：显示描述 + 完整档位（维度名:值）+ tips 列表。
- 再次点击同一行或「收起」收回。
- 保留键盘可访问（Enter 展开）。

### 5.3 新增页折叠组

- 每个折叠组头部有：标题 + 当前摘要 + 展开/收起箭头。
- 摘要示例：
  - 基本信息：「照片 · 地铁口的逆光侧脸」或「未填写标题」
  - 档位：「中长焦 / 逆光 / 侧身」
  - AI 技巧：「2 条」
- 折叠组切换不丢失已填内容。

### 5.4 删除照片

- 从照片右上角移到卡片底部操作行（与展开区相邻），或者保留在照片右上角但加大/加深。
- 删除前仍弹 Vant 确认框。

## 七、验收标准

- 首页默认态下，用户不滚动就能看到至少一张照片的主体（探索区不再占首屏）。

- 新增页从选完照片到保存，拇指操作路径不超过 3 屏滚动。
- 颜色仍只有 0.18 的 `:root` 一套，无新硬编码。

## 十、手机端专项优化（可叠加在 0.19 上）

0.18 已经做了窄屏适配和无横向溢出，但对着代码和渲染再检查，还有一批**只针对手机交互、加载、渲染**的问题。这些问题在桌面端不明显，在手机上会真实影响使用。

下面按优先级分 P0 / P1 / P2，每类都给出**代码里的具体位置和修法**。后台（`cloudbase.js`、数据表）都不动；需要改动前端调用方式的会单独说明。

### P0 — 手机上会实际出问题的

#### 1. iOS 聚焦输入框时整页放大

**问题**：`css/style.css` 里 `--van-cell-font-size: 15px`（Vant 变量区 1129 行），`van-field` 的输入框会继承这个字号。iOS Safari 只要 input/select/textarea 的字号小于 16px，聚焦时就会自动放大整页，用户必须手动缩回。

**修法**：

```css
:root {
  --van-cell-font-size: 16px; /* 原来是 15px */
}

.van-field .van-field__control {
  font-size: 16px; /* 兜底，确保任何情况下都不小于 16px */
}
```

> 这是纯 CSS 改一行，不影响 Vant 其它组件。

#### 2. 触摸设备上 hover 会「粘住」

**问题**：`css/style.css` 里大量 `:hover` 规则没有包在 `@media (hover: hover)` 里面。手指点一下后，那个灰底/变色会一直挂着，直到点别处。

**涉及规则**（实测会粘住的）：

- `.btn:hover` / `.btn.ghost:hover` / `.text-btn:hover`
- `.add-btn:hover` / `.menu-btn:hover` / `.menu-item:hover`
- `.pw-toggle:hover` / `.tip-x:hover`
- `.explore-more:hover` / `.van-uploader__upload:hover`
- `input[type="file"]:hover::file-selector-button`

**修法**：

把这些 hover 规则改成仅在支持 hover 的媒介生效：

```css
@media (hover: hover) {
  .btn:hover:not(:disabled) { ... }
  .text-btn:hover:not(:disabled) { ... }
  /* 其它同理 */
}

.btn:active:not(:disabled) { ... }   /* 触摸时保留按下反馈 */
```

> 0.18 里已经有一部分（`.tag-chip`、` .shot-del`、` .shot-toggle`）包了 `@media (hover: hover)`，说明思路对了，只是没扫全。

#### 3. 点击目标普遍小于 44×44

手机上拇指点按的最小舒适区是 44×44 CSS px。项目自身定的 `--touch-min: 40px`，先做到 40，44 留给顶栏少数几个核心键去追求。当前多处实际可点区域不够：

| 元素 | 当前尺寸 | 问题 | 实际做法 |
|------|----------|------|----------|
| `.icon-btn`（原 `.add-btn`/`.menu-btn`） | 32×32 视觉 | 顶栏核心入口太小 | `::after { inset: -5px }` → 40×40 |
| `.shot-del` | 28×28 | 删除照片容易误触 | `::after { inset: -6px }` → 40×40 |
| `.shot-toggle` | 约 24×90 | 展开卡片条数按钮太小 | 0.19a 先把按钮撑到 40×40；0.19b 再改成整行可点 |
| `.tip-x` | 22×22 | 删除一条 AI 技巧几乎点不中 | 视觉提到 32×32 + `::after { inset: -5px }` → 40×40 |
| `.tag-chip` | 约 29×60 | 胶囊按钮高度不够 | `min-height: 34px` + `::after { inset: -4px }` → 40×40 |
| `.pw-toggle` | 34×34 | 密码可见切换偏小 | `::after { inset: -3px }` → 40×40 |

**修法**（不破坏现有视觉，优先扩大热区）：

```css
/* 顶栏动作按钮：视觉 32×32，热区扩到 40×40 */
.icon-btn {
  position: relative;
}
.icon-btn::after {
  content: "";
  position: absolute;
  inset: -5px; /* 32 + 5 + 5 = 42？注意：这里扩的是 padding box，所以实际 40×40 */
}

/* 展开整行可点（0.19b） */
.shot-meta {
  min-height: 44px;
  display: flex;
  align-items: center;
}

/* 删除小 ×：视觉 32×32 + 热区扩到 40×40 */
.tip-x {
  position: relative;
}
.tip-x::after {
  content: "";
  position: absolute;
  inset: -5px;
}
```

> 0.19a 已经把 `.icon-btn` / `.shot-del` / `.shot-toggle` / `.tip-x` / `.tag-chip` / `.pw-toggle` 都处理到 ≥ 40×40。0.19b 的卡片重构再把 `.shot-toggle` 改成整行触发。

#### 4. 底部安全区没留

**问题**：目前只在 `topbar` 和 `.feed-wrap` / `.form-wrap` 顶部用了 `env(safe-area-inset-top)`，底部完全没有处理。iPhone 底部 home indicator 会遮住保存按钮。

**修法**：

```css
.form-wrap {
  padding-bottom: calc(28px + env(safe-area-inset-bottom, 0px));
}

/* 0.19 要做的底部固定保存条 */
.sticky-save {
  padding-bottom: env(safe-area-inset-bottom, 0px);
}
```

横屏时还有刘海左右边，也建议补上：

```css
body {
  padding-left: env(safe-area-inset-left, 0px);
  padding-right: env(safe-area-inset-right, 0px);
}
```

> 但注意：首页 `body.page-list { padding: 0 }` 是为了照片全出血，左右安全区需要单独处理成「照片出血，但文字块避开刘海」。

#### 5. 长文本可能撑破卡片

**问题**：`.shot-title` 和 `.shot-note` 没有 `overflow-wrap` / `word-break`。如果标题是一段长英文或 URL，会横向溢出。

**修法**：

```css
.shot-title,
.shot-note {
  overflow-wrap: anywhere;
  word-break: break-word;
}
```

#### 6. 首页一次性取全部照片

**问题**：`js/cloudbase.js` 的 `listPhotos()` 没有 `limit`，`signPhotoUrls()` 用 `Promise.all` 对所有路径同时签名。照片攒到几十张以后，手机上打开首页会同时发起几十个签名请求 + 图片请求，慢且费流量。

**修法**（**只改前端调用方式，不动后台**）：

- 在 `cloudbase.js` 的 `listPhotos(options)` 里加一个可选 `limit` 参数：

```js
async function listPhotos(options) {
  ...
  if (options && options.limit) {
    query = query.range(0, options.limit - 1);
  }
  ...
}
```

- `app.js` 启动时先取最近 30 条，滚动到底再取下一批 30 条（或加一个「加载更多」按钮）。
- 签名也分批：不要一次签 200 个 URL，只签当前要显示的那批。

> `postgREST` 的 `.range(from, to)` 已支持；接口签名保持不变，不传 `limit` 就是全部，向后兼容。

### P1 — 明显提升手机体验

#### 7. 滚动性能：`content-visibility` 跳过屏幕外卡片

**问题**：feed 一长串 `.shot` 都在首屏外参与布局，滚到后面会卡。

**修法**：

```css
.shot {
  content-visibility: auto;
  contain-intrinsic-size: auto 520px;
}
```

> 注意和 `.shot` 的入场动画兼容：入场动画只在元素进入视口时跑一次，不影响。

#### 8. 图片加载导致布局跳动（CLS）

**问题**：`.shot img` 没有 `width/height` 或 `aspect-ratio`，图片加载前没有占位，加载完会把下方内容顶下去。

**修法**：

- 简单兜底：给 `.shot img` 一个 `min-height: 240px` + 骨架色；
- 更干净的解法是上传时记录宽高比（要加列 = 动后台），所以 0.19 先用 `content-visibility` 兜底，不追完美。

#### 9. CDN 依赖影响弱网首屏

**问题**：首页要等 4 个远端 CDN 资源（Vue / Vant CSS / Vant JS / CloudBase SDK）才能渲染。手机弱网下会卡很久。

**修法**：把这几个库 vendor 进仓库（`vendor/` 目录），`deploy.sh` 一起上传，从自己的域名加载：

- 少 3 次 DNS + TLS 握手；
- 不依赖 jsdelivr / static.cloudbase.net 可达性；
- 不构建，只是把 CDN 下载的文件放进仓库。

> 注意：Vant 的 CSS 必须在 `css/style.css` 之前加载这个顺序要保持。

#### 10. Android 点击高亮

**问题**：Android WebView 上点自定义按钮会出现默认的蓝色/灰色高亮块。

**修法**：

```css
* {
  -webkit-tap-highlight-color: transparent;
}
```

同时保留自己的 `:active` 反馈，让用户知道按到了。

#### 11. 正文 13px 偏小

`.shot-note` 和 `.shot-facets` 当前 13px，手机一臂距离看略吃力。0.19 的排印规范已经把正文提到 14px，这里顺带解决。

### P2 — 可以做、但需要你先拍板

#### 12. PWA 图标与 manifest

仓库现在**没有 `manifest.json`、没有 `icons/`**，虽然 `index.html` 写了 `apple-mobile-web-app-capable=yes`，但添加到主屏后是网页截图，不是图标。

修法很小：加一个 `manifest.json` + 192×192 / 512×512 图标，就能全屏无地址栏打开。PRODUCT 把图标放在 1.0，其实现在就能做。

#### 13. 手机上加载原图太费流量

上传时压到长边 1600，但手机 feed 看的是 390px 宽缩略图，下载 1600 像素浪费流量。

修法有两条路，都需要先确认：

1. **动后台**：上传时再存一份缩略图 → 不符合「后台不用改」；
2. **CloudBase 图片处理参数**：如果托管桶是 COS 后端，可以尝试在签名 URL 后面拼 `?imageMogr2/thumbnail/800x` 这类参数。需要先验证是否支持，不支持就不能用。

所以这一条列为 P2，不急着做。

#### 14. 深色模式

手机上夜里看白底刺眼。但 0.16 你已经否过「纯白 / 暖米白 / 深色」三个整体方案中的深色，所以默认不做。如果只是想跟随系统 `prefers-color-scheme`，那是另一件事，可以单独谈。

## 十二、P1.7/P1.8 在 0.19b 撤回的记录

0.19b 原本想把 **P1.7（`content-visibility: auto` 跳过屏幕外卡片）** 顺带做掉，
现场写了：

```css
.shot {
  content-visibility: auto;
  contain-intrinsic-size: auto 560px;
}
```

无头 Chrome 立刻发现 **320–560px 视口横向溢出 75px**。根因链：

1. `contain-intrinsic-size: auto 560px` 在语法上是一个轴的取值（`auto <length>`），
   会被同时套到**宽高两轴**；离屏卡片按 560px 宽占位。
2. `.feed` 是 column flex，被跳过的卡片作为 flex item 把 min-content 顶到 560px。
3. `body { display: flex }` 让 `#app` 成了 flex item；`min-width: auto` 把它锁住，
   于是页面宽度被钉在 560px，无法收缩到视口宽度（如 415px）。

补救方向试过两个：

- 把 `contain-intrinsic-size` 改成两轴写法 `auto 0 auto 560px`，
  再补上 `body > * { min-width: 0 }`——结果页面虽然不再溢出，却会在 430px 视口
  缩到 189px 宽（因为 `flex-grow: 0` 不让它长回来）。
- 让 `#app` 强制 `width: 100%` 可以长回来，但会改变桌面顶栏宽度（超出 0.19b 范围）。

结论：**0.19b 不带 P1.7/P1.8**。

`body/#app` 的 flex-item 尺寸问题在 **0.19c 热修**里被顺带解决：
`body.page-list` 改成 `display: block`，`#app` 恢复为块级盒子（宽度 = 视口），
`flex-grow: 0` 导致的内容收窄不再存在。所以后续如果要上 `content-visibility`，
不用再绕 `min-width: auto` 那条路；但 0.19c 这次只做这个结构修复，不重新引入 CV。

`css/style.css` 里 `.shot` 的注释也留了同一句话，防止以后照着旧版 REDESIGN 直接抄。

## 十四、0.19d：新增页交互精简

起因是「这个页面的整个交互我觉得还是有点繁琐」。先把整页的操作流数了一遍，
确认繁琐属实，而且**主要不是折叠分组带来的** —— 是我在 0.19c 里新引入的两处。

### 14.1 「拿回来」从 3 下压到 1 下

改之前：点「生成提示词」→ 点「粘贴回填」→ 点输入框 → 粘贴 → 点「解析并填入」。
5 次触碰，但语义上只有两件事：把提示词给出去、把结果拿回来。

- 两颗平级按钮（生成提示词 / 粘贴回填）本身就是负担：它们是同一件事的两端，
  却要用户自己判断点哪颗，而且提示词还没生成时点「粘贴回填」也没有意义。
  现在只剩一颗主按钮，文案跟着状态走（点过一次之后变「重新复制提示词」）。
- 粘贴走 `paste` 事件直接接管（`e.clipboardData.getData("text")`），粘上就填，
  不用再点第三下。拿不到 `clipboardData` 就 `return`，放给浏览器默认粘贴，
  框下面那颗「没自动填上就点这里」是给这条降级路径留的 ——
  读不到剪贴板在各端是常态（微信内置浏览器基本拿不到），不是异常，**别当死代码删掉**。
- 不监视输入自动解析：解析失败要报错，「边打字边报错」比多点一次烦人得多。
  粘贴是一次明确的完成动作，只认它。
- 提示词只读框默认收着。那段文字是要复制的、不是要读的，占 6 行；
  只有复制失败（手抄是唯一出路，自动展开）或用户自己想核对时才展开。
- 生成之后**不自动聚焦**粘贴框：点完这颗键人是要切到 AI 那边去的，
  这时候弹键盘只会挡住正要发出去的照片。
- 解析失败时把光标放回框里，让人就地改那一处再试（原文留在框里，只报错不丢内容）。

### 14.2 单选维度从弹层改回行内展开

0.19c 用 `van-picker` 弹层，一维只选一个值却要「点行 → 滚轮 → 点确认」三下；
改成点行后在**这一行下面**展开候选胶囊，两下就够，而且维度名和已选值一直留在视野里
（遮罩会把它们一起挡掉）。

- 手风琴（同时只开一行）：核对时本来就是一次看一个维度，
  而且展开态的高度上限因此固定成一行，改五个维度也不会把页面越拉越长。
- 选中后自动收起（动作闭环：展开 → 点 → 收），反馈没丢 ——
  收起后上面那一行的值会当场更新。取消时反过来留着展开，人通常接着要换个别的值。
- **弹层里的「不填」出口由「再点一次选中的值 = 取消」承担**。
  `P5Facets.toggle` 本来就是这语义，和姿势胶囊、首页筛选一致，`facetHint` 里写明了。
  代价是没有一条显式的清空按钮，但全站语义一致更值。
- 展开区不缩进、用满内容宽度：缩进到「值」那一列对齐更好看，
  但 390px 下只剩约 290px，一个「中长焦」就把行折了。
  实测 320/390 折两行、430 一行；AI 追加 loose 值时会多一个胶囊、多折一行，可接受。
- 边界线挪到 `.facet-item`（行 + 展开区共用一条）：挂在行上的话，
  展开时会先看到一条线、再看到线下面冒出一排胶囊，读起来像「下面那段属于另一行」。

### 14.3 评估后**没做**的两件事

- **两阶段提交**（先存照片 + 标题 + 描述就能保存，AI 分析改成事后在卡片上补）：
  这个能砍掉一半步骤，但和已拍板的「分类和标签化是核心循环的一部分，
  不是可选的『以后再补』」直接冲突，所以不推荐。
- **让「基本信息」组头摘要反映 AI 进度**：回填后档位组有值、技巧组有条数，
  信息没丢；这个组再报一句只是冗余。

站外那 4 步（切 app、发图、粘提示词、取回 JSON）是「无云函数」硬约束的代价，
站里不接 AI 就省不掉 —— 页面设计解决不了，1.5 直连后自然消失。
